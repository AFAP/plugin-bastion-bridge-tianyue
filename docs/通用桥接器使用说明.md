# 通用堡垒机 SSH 桥接器使用说明

> 本文面向运维人员与 AI 助手，说明如何通过本地桥接器操作已由天玥运维安全网关建立的 SSH 会话。

> **版本标记**：桥接器 `1.1.0-om6.0.7.0`，适用堡垒机客户端 `OMClientPlus 6.0.7.0`
> （升级后实测通过）。旧客户端 `6.0.4.16603` 请使用 `1.0.0-om6.0.4.16603` 包，详见
> [README](../README.md#0-版本与适用堡垒机)。

## 0. 端口约定

桥接器默认仅监听 `127.0.0.1:8765`。若端口已占用，会自动尝试 `8766`、`8767` 等后续端口，
并把当前地址写入：

```text
%LOCALAPPDATA%\sshbridge\TianYueSSHBridge\active_port.txt
```

下文以 `<BASE>` 表示该文件中的实际地址，例如 `http://127.0.0.1:8765`。

## 1. 工作方式

天玥控制台把 SecureCRT 风格的连接参数传给本地 `tianyue_ssh_bridge.exe`。
桥接器解析参数、连接 SSH，然后向本机程序提供 HTTP、SSE 与 Socket.IO 接口。

```text
天玥控制台 ──唤起并传参──▶ 桥接器 ──SSH──▶ 目标服务器
                              ▲
                              └── 127.0.0.1:<端口> ◀── AI / 脚本
```

## 2. 使用流程

1. 从 GitHub Release 下载 `tianyue_ssh_bridge.exe` 并核对 SHA-256。
2. 在天玥控制台的本地工具配置中，把 SSH/SecureCRT 工具路径指向该 EXE。
3. 点击已获授权的 SSH 资源，等待桥接器建立连接。
4. 读取 `active_port.txt`，执行健康检查：

```bash
curl http://127.0.0.1:8765/health
```

响应：

```json
{
  "status": "ok",
  "connected": true,
  "version": "1.1.0-om6.0.7.0",
  "bridge_version": "1.1.0",
  "bastion": {"client": "OMClientPlus", "version": "6.0.7.0"}
}
```

只有 `connected: true` 时才继续执行命令。`version` / `bridge_version` / `bastion` 为版本标记：
可用于确认当前运行的桥接器版本，以及它按哪个堡垒机客户端版本验证过。旧版桥接器不返回这些
字段，调用方应容忍其缺失。

## 3. API 说明

### 3.1 健康检查

```http
GET <BASE>/health
```

响应字段：

| 字段 | 说明 |
|---|---|
| `status` | 固定为 `ok`，表示 API 进程存活 |
| `connected` | SSH 会话是否已建立 |
| `version` | 完整版本号，如 `1.1.0-om6.0.7.0` |
| `bridge_version` | 桥接器版本，如 `1.1.0` |
| `bastion.client` | 适用的堡垒机客户端名称，如 `OMClientPlus` |
| `bastion.version` | 已验证的堡垒机客户端版本，如 `6.0.7.0` |

### 3.2 执行单次命令

```http
POST <BASE>/execute
Content-Type: application/json

{"command": "uname -a", "timeout": 30}
```

响应：

```json
{"stdout": "Linux ...\n", "stderr": "", "exit_code": 0}
```

- `timeout` 可选，默认 30 秒。
- `exit_code` 为 `0` 表示成功，非 `0` 表示远端命令失败，`-1` 表示 SSH 未连接或执行异常。
- `exit_code` 为 `126` 表示命中桥接器的**本地危险操作兜底**：命令没有下发到服务器，
  `stderr` 中是可读提示。遇到时如实告知用户，不要改写命令绕过拦截；确需执行由授权人员手动完成。

### 3.3 流式输出（SSE）

```http
GET <BASE>/stream?command=ping%20-c%204%20127.0.0.1
```

事件序列：`start` → 若干 `stdout` / `stderr` → `exit` → `end`；异常时包含 `error`。

### 3.4 交互输入

```http
POST <BASE>/input
Content-Type: application/json

{"data": "y\n"}
```

未经用户明确授权，不要自动发送确认、密码或其他交互输入。

交互输入写入桥接器的持久 shell 通道，因此**只有在 `ssh_prefer_shell=true` 时才能真正
送进正在执行的命令**（默认的 exec 通道没有可交互的 stdin）。

### 3.5 Socket.IO

连接同一 HTTP Origin，使用 Socket.IO 默认路径 `/socket.io/`。可发送 `execute`、`stream`、`input`
事件，并接收 `result`、`start`、`output`、`end`、`input_status` 等事件。

## 4. 使用建议

| 场景 | 推荐接口 |
|---|---|
| 健康检查 | `GET /health` |
| 30 秒内完成的查询 | `POST /execute` |
| 长时间或持续输出 | `GET /stream` 或 Socket.IO `stream` |
| 需要交互输入 | `POST /input` 或 Socket.IO `input` |

每次执行后都检查 `exit_code`。不要因为命令失败而盲目重复执行具有副作用的操作。

## 5. 安全注意

- API 无鉴权但仅监听 `127.0.0.1`；**本机其他进程仍可能调用它**。
- 不要把命令输出中的密码、密钥、令牌或业务数据转发到本机之外。
- 删除、重启、防火墙、磁盘格式化、数据库写入等高风险命令必须先获得明确授权。
- 不要尝试绕过堡垒机审计、提权或清理历史记录。

## 6. 排错

| 现象 | 处理 |
|---|---|
| `active_port.txt` 不存在 | 桥接器尚未被唤起；重新点击天玥 SSH 资源 |
| API 连接被拒 | 重新读取端口文件，不要假定始终是 `8765` |
| `/health` 为 `connected: false` | 查看本地日志中的认证、网络或参数解析错误 |
| `exit_code: -1` | SSH 已断开；重新执行健康检查，必要时重连资源 |
| `exit_code: 126` | 命中本地危险操作兜底，命令未下发；如实告知用户，不要改写命令绕过 |
| 提示 `SecureCRT工具版本太低` | 客户端版本高于桥接器标注的版本，换用对应 `-om` 版本包 |
| 命令超时 | 增大 `timeout` 或改用 `/stream` |

日志位置：

```text
%LOCALAPPDATA%\sshbridge\TianYueSSHBridge\logs\bridge.log
```

桥接器控制台默认以 `>>>` 展示脱敏后的参数/指令，以 `<<<` 展示服务器返回、退出码与耗时。
命令和返回正文只显示在当前窗口，不写入上述日志文件；交互输入正文始终隐藏。

## 7. Python 示例

```python
import json
import urllib.request

BASE_URL = "http://127.0.0.1:8765"  # 用 active_port.txt 中的实际地址替换

request = urllib.request.Request(
    f"{BASE_URL}/execute",
    data=json.dumps({"command": "df -h", "timeout": 30}).encode("utf-8"),
    headers={"Content-Type": "application/json"},
)

with urllib.request.urlopen(request, timeout=35) as response:
    print(json.loads(response.read().decode("utf-8")))
```
